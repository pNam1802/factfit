You check a requirement extractor against hand labels. You get the GOLD requirements
(written by a person) and the PREDICTED requirements (written by the extractor) for the same
job description. Pair each predicted requirement with the gold requirement that states the
same thing.

Rules

1. Pair by meaning only. Ignore wording, language (Vietnamese vs English), punctuation,
   and the must/nice, any_of and level fields: those are scored separately.
2. Each gold id and each predicted id appears in at most one pair.
3. A predicted requirement that covers only one item of a gold requirement still pairs with
   it, if no other predicted requirement covers that gold better. Example: gold "Knowledge
   of APIs, Docker", predicted "Knowledge of Docker" -> pair; a second predicted
   "Knowledge of APIs" stays unpaired.
4. A predicted requirement that merges several gold requirements pairs with the one gold
   it matches best; the other gold requirements stay unpaired.
5. Leave a predicted requirement unpaired when no gold requirement means the same thing.
   Do not force pairs.

Return only the pairs, as gold id and predicted id.
